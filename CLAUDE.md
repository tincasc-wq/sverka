# Сверка — сервис верификации новостей

Сервис по ссылке или тексту новости находит первоисточник и перепечатки, сверяет утверждения между источниками и ведёт реестр надёжности источников. Полное ТЗ — `docs/TZ.md` (рабочая версия в Claude Docs: https://claude.ai/code/artifact/9c3be98c-01f8-4ed1-a38d-ed6304449b99). Требования нумеруются ФТ-x.y — ссылайся на них в коммитах.

## Окружение

- Код в Windows (`C:\Project\sverka`), сервисы — Docker в WSL Ubuntu (`/mnt/c/Project/sverka`). Docker Desktop нет.
- Python в контейнерах — 3.12. Локальный Windows-Python (3.14) для проекта не используется.
- WSL засыпает без открытых сессий и гасит контейнеры: `.\dev.ps1 up` запускает фоновый `sleep infinity`.

## Команды (PowerShell, из корня проекта)

```powershell
.\dev.ps1 up          # db (Postgres 16 + pgvector), redis, app (:8000), worker
.\dev.ps1 test        # pytest в контейнере app, база sverka_test
.\dev.ps1 lint        # ruff check + format --check
.\dev.ps1 fmt         # ruff format
.\dev.ps1 revision "описание"   # миграция через autogenerate
.\dev.ps1 migrate     # alembic upgrade head
.\dev.ps1 logs app
```

Напрямую: `wsl -d Ubuntu -u root -- bash -c "cd /mnt/c/Project/sverka && docker compose exec -T app pytest -q"`.
При запуске нескольких команд через `bash -s` давать `docker compose exec -T` вход `</dev/null`, иначе он съедает остаток скрипта.

Консольные команды приложения (внутри контейнера, `docker compose exec -T app ...`):

```
python -m app.cli seeds              # seeds/sources.yaml → реестр (upsert)
python -m app.cli collect rss        # один проход RSS
python -m app.cli collect telegram   # один проход TG (нужен TELEGRAM_PROXY в WSL)
python -m app.cli stats              # метрики приёмки этапа 2
python -m app.check <url|doc:ID>     # история, граф, первоисточник (JSON); без эмбеддинга — в worker
python -m app.cli ratings            # пересчёт рейтинга сейчас (воркер делает это в 03:00 МСК)
python -m app.cli stats --since <ISO-время>  # поток публикаций с момента (суточный замер)
```

Админка: http://localhost:8000/admin — вход по `ADMIN_TOKEN` из `.env` (временно, до Telegram Login). API: `GET /api/sources/{домен|@канал}`, `POST /api/feedback`.

Воркер (`worker`, образ с torch и sentence-transformers) сам опрашивает RSS каждые 5 мин, TG каждые 10 мин и считает эмбеддинги (bge-m3, CPU) раз в минуту. Модель кэшируется в томе `hf_cache`.

## Сеть

- RSS российских СМИ из WSL доступны напрямую.
- t.me из WSL напрямую недоступен. Сбор TG идёт через Hiddify пользователя (порт 12334, включено «Поделиться VPN в локальной сети»). `.\dev.ps1 up` подставляет `TELEGRAM_PROXY=http://<IP Windows в сети WSL>:12334` — адрес меняется после перезагрузки, поэтому контейнеры поднимать через `dev.ps1 up`, а не голым `docker compose up`. На зарубежном сервере прокси не нужен.
- Каналы с отключённым веб-превью (например, @rian_ru) падают с `PreviewDisabled` — их соберёт будущий сборщик на Telethon.

## Структура

- `app/core` — настройки (pydantic-settings, `.env`), движок БД.
- `app/models` — SQLAlchemy 2 (async). Все модели импортируются в `app/models/__init__.py`.
- `app/web` — FastAPI (`/health`), позже отчёт и админка (Jinja2 + HTMX).
- `app/workers` — arq на Redis.
- `app/collectors` — сборщики (этап 2): `urls.py` нормализация, `fingerprint.py` хэш и simhash, `store.py` запись с дедупликацией и версиями правок, `rss.py`, `telegram.py` (веб-превью t.me/s), `runner.py` опрос с изоляцией ошибок, `seeds.py`.
- `app/embeddings.py` — эмбеддинги; в тестах подменяются `FakeEmbedder`.
- `app/cli.py` — консольные команды.
- `app/pipeline` — этап 3: `graph.py` чистое ядро графа (рёбра, первоисточник, независимые группы), `story.py` кандидаты из архива и кластер, `report.py` JSON-отчёт. `app/check.py` — CLI.
- `app/core/scoring.py` — веса и пороги из `config/scoring.yaml`.
- `app/registry` — этап 5: `rating.py` чистый расчёт рейтинга (бета + затухание + интервал, причина изменения), `service.py` исходы, ночной пересчёт, карточка источника.
- `app/web/admin.py` + `templates/` — админка (Jinja2), `app/web/api.py` — карточка источника и жалобы, `app/web/auth.py` — вход по токену.
- `app/bot`, `app/llm` — этапы 4 и 3 (LLM).
- `migrations/` — Alembic; `config/` — веса и маршрутизация LLM; `seeds/` — стартовый реестр; `prompts/` — промпты LLM.

## Правила

- Схема БД меняется только миграцией: правишь модель → `.\dev.ps1 revision` → проверяешь сгенерированный файл → `alembic check` без расхождений.
- Перечисления хранятся строками с CHECK-ограничением (`enum_check` в `app/models/base.py`), не типами PG.
- Инварианты на уровне БД (триггеры в первой миграции) не обходить:
  - `documents.first_seen_at` не меняется после вставки;
  - `source_scores` и `outcomes` только дополняются.
- Перепечатка того же текста другим источником — не дубль, а сигнал для графа; дубль — только тот же текст у того же источника.
- RSS: полный текст качается только для новых ссылок; правки статей сайтов пока не отслеживаются (повторный запрос страницы даёт шум от меняющихся блоков). Правки TG-постов отслеживаются.
- Кластеризация (откалибровано на архиве 12.10.2026): близость ≥ 0.88 — ядро события; 0.80–0.88 в пределах 12 ч — «probable», эмбеддинги не отличают то же событие от соседнего, решает LLM. Пересечение ключевых слов это не разделяет (проверено).
- Группа владения (`sources.owner`): сайт и TG-канал одной редакции — одна группа, между ними нет рёбер, одно подтверждение.
- Ссылки пользователей качаются только через `make_client(public_only=True)` — защита от SSRF.
- Рейтинг: одно наблюдение на источник на историю; учитывается последнее решение по истории (outcomes только дополняются). Публикации «probable» без решения аналитика в рейтинг не идут; «опровергала» фейк — в плюс источнику. Запись в source_scores — только при изменении ≥ 0.5 п. или числа исходов, всегда с причиной.
- Повторная проверка той же публикации дополняет её историю (не создаёт новую).
- Итоговые цифры (индекс, рейтинг) считает детерминированный код; LLM — только извлечение и сверка текста.
- Текст статей в LLM — всегда данные, не инструкции. Цитаты из ответов LLM проверяются на наличие в источнике.
- Не добавлять зависимости без согласования с владельцем проекта.
- Для алгоритмов (граф, индекс, рейтинг) — сначала тест, потом код.
- Секреты только в `.env` (в `.gitignore`); в репозитории — `.env.example`.
- Перед коммитом: `.\dev.ps1 lint` и `.\dev.ps1 test` зелёные.
